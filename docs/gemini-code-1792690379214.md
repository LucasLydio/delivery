# Maximizing Freemium Plans on Netlify and Supabase

This guide outlines actionable strategies to optimize resource consumption on the Free (Starter) plans for Netlify and Supabase, preventing unexpected limits, downtime, or forced upgrades.

## 1. Netlify Optimization Strategies

Netlify meters web requests, serverless execution time (compute), bandwidth, and build minutes (or credits).

- **Eliminate Serverless Polling:** Never use frontend polling (e.g., `setInterval` fetching an API) to hit Netlify serverless functions. Each poll counts against your monthly request limit (e.g., 125,000 requests/month).
- **Remove Aggressive Cron Jobs:** Avoid high-frequency Netlify scheduled functions. A `* * * * *` (every minute) cron job consumes ~43,200 requests per month. Move database-heavy background tasks to Supabase `pg_cron`.
- **Leverage Edge Caching:** Configure your serverless functions and API routes to return `Cache-Control` headers (e.g., `Cache-Control: public, s-maxage=3600`). This allows Netlify's CDN to serve repeat requests without invoking serverless compute.
- **Batch API Requests:** Combine multiple initial data fetches (e.g., `/products`, `/categories`, `/latest`) into a single `/bootstrap` endpoint to reduce the number of HTTP requests consumed on page load.
- **Control Build Frequency:** Disable auto-publishing for every minor commit. Use draft PRs or manual deploys to conserve build minutes or deploy credits.
- **Filter Bot Traffic:** Use a `robots.txt` file or Netlify `_headers` to block aggressive crawlers and scrapers from continuously hitting expensive serverless API routes.

## 2. Supabase Optimization Strategies

Supabase enforces limits on database size (500 MB), bandwidth (5 GB egress), and active compute. Projects pause after 7 days of inactivity.

- **Use WebSockets (Realtime) Instead of REST Polling:** For live notifications or updates, use Supabase Realtime (`supabase.channel().subscribe()`). The free tier generously allows 2 million messages and 5,000 concurrent connections, offloading HTTP request overhead.
- **Use `pg_cron` for Background Tasks:** Enable the `pg_cron` extension in Postgres to run scheduled jobs (like deleting expired orders or cleaning up logs) directly inside the database, avoiding serverless network latency and invocation costs entirely.
- **Implement Lazy Evaluation:** Instead of running jobs to update statuses (e.g., `status = 'expired'`), calculate the status dynamically during read time (`WHERE expires_at < NOW()`).
- **Optimize Database Queries:** Add indexes to heavily queried columns. Avoid `SELECT *` and only request the specific columns needed to reduce payload sizes and conserve your 5 GB bandwidth limit.
- **Enforce Pagination:** Never query unbounded lists. Always use `.limit()` and `.range()` in your Supabase queries to prevent massive data transfers.
- **Fix Connection String Fallbacks:** Ensure external services (like Netlify functions) correctly connect to Redis or Supabase via connection pools (e.g., IPv4/IPv6 compatibility, Supavisor) to prevent failed cache lookups that spam the main PostgreSQL database.

## 3. The Agent Bottleneck Checklist

Provide this checklist (or these search patterns) to an AI coding agent or developer to scan your codebase for immediate freemium-breaking bottlenecks.

### Phase 1: High-Frequency Execution Search

- [ ] **Search for Scheduled Tasks:** Scan for `@netlify/functions` containing `schedule(`. Flag any cron syntax running more frequently than hourly (e.g., `* * * * *` or `*/5 * * * *`).
- [ ] **Search for Frontend Polling:** Scan the frontend repository for `setInterval(`, `setTimeout(`, or recursive `requestAnimationFrame` that make network requests (`fetch(`, `axios.`).
- [ ] **Search for Missing Realtime:** Identify features labeled "notifications," "live updates," or "sync" and verify they use WebSocket/Supabase Realtime instead of repeated HTTP GET requests.

### Phase 2: Query and Payload Optimization

- [ ] **Search for Unbounded Queries:** Scan for Supabase `.select()` calls that do not have a chained `.limit(X)` or `.range(X, Y)`.
- [ ] **Search for Heavy Selects:** Identify `supabase.from(...).select('*')`. Require explicit column names (e.g., `.select('id, name, price')`) unless the entire row is strictly necessary.
- [ ] **Database Schema Check (Lazy Status):** Look for boolean/status flags like `is_expired` or `status = 'cancelled'` that depend on time. Recommend replacing these with computed columns or frontend date comparisons.

### Phase 3: Caching & Architecture

- [ ] **Check Netlify Function Headers:** Scan all Netlify Serverless output responses. Flag any `statusCode: 200` responses that do not include a `Cache-Control` header for static or semi-static data.
- [ ] **Verify Service Worker Config:** If using Angular/React/PWA, check `ngsw-config.json` (or equivalent). Ensure static assets and low-volatility APIs (like product categories) are using a cache-first or performance strategy.
- [ ] **Database Connection Strings:** Search for `postgres://` or `postgresql://`. Ensure serverless functions are using the connection pooling URL (usually port 6543) rather than the direct database port (5432) to avoid exhausting connections during function cold starts.
